## 1. Testing Methodology

The security verification framework utilizes automated integration and unit testing directly against the Express application instance, Mongoose data models, and MongoDB Atlas database.

### 1.1 Multi-Layered Testing Strategy
1. **Broken Access Control & Privilege Escalation (A01:2025):**
   - Synthesizing valid JWTs for multiple roles (`student` vs. `coordinator`).
   - Testing Broken Function Level Authorization (BFLA) by submitting coordinator-only mutations with student credentials.
   - Testing Insecure Direct Object Reference (IDOR) / BOLA by attempting to retrieve other students' issue records and approving unauthorized renewals.
2. **Security Misconfiguration & Headers (A02:2025):**
   - Inspecting HTTP response headers generated by `helmet` (`nosniff`, `Content-Security-Policy`, `Referrer-Policy`).
   - Simulating malicious cross-origin preflight and fetch requests (`Origin: https://malicious-phishing-site.com`) to verify strict CORS rejection.
   - Asserting error handling middleware suppresses internal stack traces in 404/500 responses.
3. **Cryptographic Failures & JWT Integrity (A04:2025):**
   - Signature tampering: Verifying rejection of tokens forged with arbitrary symmetric secrets.
   - Token expiration: Verifying rejection of tokens past their `exp` window.
   - Algorithm confusion: Forcing `algorithm: 'none'` in token headers and asserting immediate 401 rejection.
4. **Injection & Input Sanitization (A05:2025):**
   - Unit testing `sanitizeObject()` with nested NoSQL operator injection vectors (`$gt`, `$ne`, `$where`, `$regex`).
   - Validating ReDoS metacharacter neutralization via `escapeRegex()`.
5. **Cross-Site Request Forgery (A08:2025):**
   - Testing cookie-authenticated state mutations against unauthorized origins and asserting `403 Forbidden` (`CSRF Protection`).
   - Verifying legitimate application requests originating from `http://localhost:5173` with anti-CSRF headers pass successfully.
6. **Session & Cookie Lifecycle:**
   - Verifying `/auth/logout` explicitly clears `access_token` and `XSRF-TOKEN` cookies.

## 6. Residual Risks & Recommended Operational Controls

1. **Supply Chain Dev Dependencies (A03:2025):**
   - Transitive build tools (`@mapbox/node-pre-gyp` through bcrypt, `tinypool` and `esbuild` through Vitest/Vite) reported advisories in `npm audit`.
   - Running `npm audit fix --force` would install breaking major versions (`vitest@5`, `tailwindcss@4`, `vite@8`, `react-router-dom@7`).
   - *Recommendation:* Schedule a planned upgrade sprint to migrate Vite and Tailwind to their latest major releases.
2. **Reverse Proxy Configuration:**
   - In production environments fronted by Cloudflare, NGINX, or AWS CloudFront, `app.set('trust proxy', 1)` must be enabled so that `express-rate-limit` tracks real client IPs rather than the load balancer's internal IP.
3. **Database Network Isolation:**
   - MongoDB Atlas network access should be restricted to specific production server IP addresses or VPC peering instead of `0.0.0.0/0`.
